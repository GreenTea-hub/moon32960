# 端到端案例：登入应答、加密上报与两套规则对比

```bash
moon run cmd/main -- case login       # 登入应答（车端，附录 B）
moon run cmd/main -- case encrypted   # AES128 加密上报
moon run cmd/main -- case report      # 实时上报：车端校验正确不应答
moon run cmd/main -- case resend      # 断线补发
moon run cmd/main -- case platform    # 车端 vs 平台间应答规则对比
```

---

## 案例一：登入应答端到端（车端，附录 B）

### ① 终端命令包

```
232301fe4c47574546344135364d463132333435360100251a0b12091e000001383938363036323031383030303132333435363701074241542d413031d5
```

| 偏移 | 字节 | 字段 | 取值 |
|---|---|---|---|
| 0 | `23 23` | 起始符 | `##` |
| 2 | `01` | 命令单元 | 车辆登入 |
| 3 | `fe` | 应答标志 | **命令包** |
| 4 | `4c47…3536` | VIN | `LGWEF4A56MF123456` |
| 21 | `01` | 加密方式 | 不加密 |
| 22 | `00 25` | 数据单元长度 | 37 |
| 24 | `1a0b12091e00` | 登入时间 | 2026-11-18 09:30:00 |
| 30 | `0001` | 登入流水号 | 1 |
| 32 | `3839…3637` | ICCID | `89860620180001234567` |
| 52 | `01` | 储能子系统数 | 1 |
| 53 | `07` | 编码长度 | 7 |
| 54 | `4241542d413031` | 子系统编码 | `BAT-A01` |
| 61 | `d5` | 校验码 | BCC(2→60) |

### ② 平台应答（附录 B.3.3.2 口径）

**只变更应答标志、应答报文时间，重新计算校验位，其余报文内容与主动发送报文一致。**

```
232301014c47574546344135364d463132333435360100251a0b12091e000001383938363036323031383030303132333435363701074241542d4130312a
```

与请求逐字节比对：

| 字段 | 请求 | 应答 |
|---|---|---|
| 应答标志 | `fe` | `01` |
| 数据单元 | 37 字节登入数据 | **完全相同**（37 字节） |
| 校验码 | `d5` | `2a`，随标志变化重算 |

需要把报文时间换成应答时刻时，只替换数据单元前 6 字节，其余保持：

```moon
build_response(request, Success, answer_time=Some(at))
```

代码还提供另外两种形态并明确标注出处，避免把联调口径当成合规：
- `TimeOnly`：保留 6 字节报文时间、删其余内容（部分地方标准口径）；
- `EmptyPayload`：数据单元为空，**不与任何条文对应**，仅供联调。

### ③ 同一 VIN 再次登入

2016 版表 4 只有 0x01/0x02/0xFE，VIN 重复落在 0x02：

```
232301024c47574546344135364d463132333435360100251a0b12091e000001383938363036323031383030303132333435363701074241542d41303129
```

若显式启用 `ResponseProfile::Extended`（地方标准 / 2025 版口径），应答标志改为 `03`。

### ④ 登入校验失败

附录 B.1 原文：校验错误时"忽略所接收数据"。因此平台**不回应答**，终端靠 3 分钟超时重发；连续 3 次无应答应间隔 30 分钟重连，并把链路恢复前存储的数据补发。

## 案例二：AES128 加密上报端到端

密钥由部署方约定：AES128-ECB，`000102030405060708090a0b0c0d0e0f`。

### ① 明文数据单元（37 字节）

```
1a0b12091f0001010201026f0001e2400e1075944e010404b01e01050006f013c80260f688
```

### ② 加密后组帧

```
232302fe4c47574546344135364d463132333435360300304c2229bb4dc2e406c63d054d69f47cbc725f02e50d74f0e58f4b78c3309bcaf466c0da206dbc7e84c0580854cd83ea3af4
```

| 字段 | 值 | 说明 |
|---|---|---|
| 加密方式 | `03` | AES128 |
| 数据单元长度 | `0030` = 48 | 37 字节明文 PKCS#7 填充后加密 |
| 校验码 | `f4` | **在密文之上**计算，先加密再校验 |

### ③ 平台处理

```
平台结论    : report-accepted
说明        : 校验正确，按附录 B.2.1 车端不做应答
```

平台依次：验 BCC（密文）→ 解密 → 去填充 → 解析信息体。字段为 SOC 78%、车速 62.3 km/h、经度 116.397000、纬度 39.909000。

### ④ 未注入密钥

```
平台结论    : rejected
说明        : 加密帧无法解密（缺 aes128 密钥），也无法按同加密方式应答，只记录
应答帧      : 无
```

这里**不出应答**是有意的：附录 B 应答要保持原加密方式，拿不到密钥就无法产出合规应答，给出一个不加密的应答反而会被判为不符合。

## 案例三：实时上报——车端不应答

```
平台结论    : report-accepted
说明        : 校验正确，按附录 B.2.1 车端不做应答
应答帧      : 无
```

校验失败时才回 0x02（数据单元按附录 B 与请求一致）：

```
平台结论    : rejected
说明        : 上报数据单元校验失败，应答 0x02；终端间隔 1min 重发至多 3 次
```

## 案例四：断线补发

```
09:31 实时  : report-accepted（车端不应答）
模拟链路中断 09:32~09:35，终端缓存三帧
补发 09:32 : resend-accepted（车端不应答）
补发 09:33 : resend-accepted（车端不应答）
计数：实时 1、补发 2
```

补发帧与实时帧数据单元相同，仅命令单元 `02 → 03`、采集时间后移。7 日外的补发应答 0x02。

## 案例五：车端与平台间规则对比

同一份实时上报数据，两个场景结论不同：

### ① 车端

```
平台结论    : report-accepted
说明        : 校验正确，按附录 B.2.1 车端不做应答
应答帧      : 无
```

### ② 平台间（正文 5.2.2，规范性）

```
平台结论    : report-accepted
说明        : 校验正确，按 5.2.2 平台间仍须正确应答 0x01
应答帧      : 23230201504c415446524d303030303030303030310100251a0b12091f00…85
应答标志    : 01
应答数据单元: 37 字节
```

### ③ 方向检查

平台侧收到下行命令 `0x08 终端校时`：

```
平台结论    : conflicting-direction
说明        : 命令 terminal-time-sync 不属于车载终端上行命令，应答 0x02
```

这条检查就是防止"把车端规则套到平台间"或反过来——第三次驳回指出的正是这个混淆。

## 附：两套规则速查

| 命令 | 车端（附录 B） | 平台间（第 5 章） |
|---|---|---|
| 0x01 登入 | 应答 0x01；失败不应答 | 方向不符 |
| 0x02 实时 | **正确不应答** | **正确应答 0x01** |
| 0x03 补发 | 正确不应答 | 正确应答 0x01 |
| 0x04 登出 | 应答 0x01（惯例） | 方向不符 |
| 0x05/0x06 平台 | 方向不符 | 应答 0x01 |
| 0x07 心跳 | 应答 0x01（惯例） | 方向不符 |
| 0x08/0x80 下行 | 方向不符 | 方向不符 |
