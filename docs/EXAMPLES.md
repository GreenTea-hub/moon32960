# 端到端案例（GB/T 32960.3-2025）

```bash
moon run cmd/main -- case login        # 登入（表 6 新模型）与应答
moon run cmd/main -- case keyexchange  # 密钥交换（表 31）
moon run cmd/main -- case activate     # 激活（表 B.3/B.4）
moon run cmd/main -- case encrypted    # AES 加密上报
moon run cmd/main -- case report       # 实时上报：车端不应答
moon run cmd/main -- case resend       # 断线补发
moon run cmd/main -- case platform     # 车端 vs 平台间
```

## 案例一：车辆登入（表 6 新模型）

### ① 终端命令包

```
242401fe4c47574546344135364d463132333435360100361a0b19091e000001383938363036323031383030303132333435363701014c4650424154323032353131323530303030303030303031ff
```

数据单元 54 字节（长度字段 `00 36`），逐段：

| 段 | 字节 | 字段 | 取值 |
|---|---|---|---|
| 0 | `24 24` | 起始符 | `$$`，2025 版 |
| 2 | `01` | 命令标识 | 车辆登入 |
| 3 | `fe` | 应答标志 | 命令包 |
| 4 | `4c47…3536` | 唯一识别码 | `LGWEF4A56MF123456` |
| 21 | `01` | 加密方式 | 不加密 |
| 22 | `00 36` | 数据单元长度 | 54 |
| 24 | `1a0b19091e00` | 数据采集时间 | 2026-11-25 09:30:00 |
| 30 | `0001` | 登入流水号 | 1 |
| 32 | `3839…3637` | ICCID | `89860620180001234567` |
| 52 | `01` | **电池管理系统数 n** | 1 |
| 53 | `01` | **BMS 对应动力蓄电池包个数 m** | 1 |
| 54 | `4c46…3031` | **动力蓄电池包编码**（24 字符） | `LFPBAT202511250000000001` |
| 78 | `ff` | 校验码 | BCC(2→77) |

长度核对：6 + 2 + 20 + 1 + 1 + 24 = **54**，与 `00 36` 一致。

**这是 2025 版与 2016 版的关键差异**：2016 版是「储能子系统数 + 编码长度 m + 变长编码」，2025 版改为「BMS 数 + 每系统包个数 + 24 位包编码（GB/T 34014）」，没有编码长度字段。

### ② 平台应答

```
242401014c47574546344135364d463132333435360100061a0b19091e003d
```

| 字段 | 请求 | 应答 |
|---|---|---|
| 应答标志 | `fe` | `01` 成功 |
| 数据单元长度 | `0036` = 54 | `0006` = 6 |
| 数据单元 | 登入数据 | 只保留 6 字节报文时间 |
| 校验码 | `ff` | `3d` |

依据 6.3.2 / B.3.3.2：变更应答标志，保留报文时间，删除其余报文内容，重算校验。

### ③ 重复登入

```
242401034c47574546344135364d463132333435360100061a0b19091e003f
```

应答标志 `03` = VIN 重复（表 4）。

### ④ 登入校验失败

附录 B.1：平台忽略所接收数据、不回应答；终端 3 分钟后重发，连续 3 次无应答应间隔 30 分钟重连。

## 案例二：密钥交换（命令 0x0B，表 31）

### ① 终端命令包

```
24240bfe4c47574546344135364d4631323334353601001f030010000102030405060708090a0b0c0d0e0f1a0b19091e001a0c19091e00da
```

数据单元 31 字节（`00 1f`）：

| 段 | 字段 | 取值 |
|---|---|---|
| 0 | 密钥类型 | `03` = AES |
| 1 | 密钥长度 | `0010` = 16 字节 |
| 3 | 密钥 | `000102…0e0f` |
| 19 | 启用时间 | 2026-11-25 09:30:00 |
| 25 | 失效时间 | 2026-12-25 09:30:00 |

长度核对：1 + 2 + 16 + 6 + 6 = **31**。

### ② 平台应答

```
24240b014c47574546344135364d4631323334353601000603001000010238
```

应答标志 `01` 成功，数据单元为 6 字节报文时间（沿用请求开头时间）。

### ③ 平台结论与责任

```
平台结论    : key-exchange-accepted
说明        : 密钥交换：类型 AES，16 字节，生效 2026-11-25 09:30:00，
              失效 2026-12-25 09:30:00；结构已校验，密钥安装由部署方完成
```

- **本项目**：解析表 31 结构、校验密钥类型与有效期、应答 0x01；
- **部署方**：把密钥装进密钥管理系统，按启用/失效时间切换；
- 本项目不持有密钥内容、不以明文落库。

## 案例三：激活（命令 0x09，表 B.3/B.4）

### ① 终端命令包

```
242409fe4c47574546344135364d463132333435360100361a0b19091e00434849503031323334353637383930310004aabbccdd4c47574546344135364d463132333435360100021122000233448c
```

数据单元 54 字节：

| 字段 | 内容 |
|---|---|
| 数据采集时间 | 2026-11-25 09:30:00 |
| 芯片 ID | `CHIP012345678901`（16 字符） |
| 公钥长度 | `0004` |
| 公钥 | `aabbccdd` |
| VIN | `LGWEF4A56MF123456` |
| 签名信息 | 类型 `01`、R `1122`、S `3344` |

### ② 平台应答（命令 0x0A，不是普通 0x01/0x02）

```
24240a014c47574546344135364d4631323334353601000201002c
```

| 字段 | 取值 |
|---|---|
| 命令标识 | `0a` 激活应答（下行） |
| 数据单元 | `01 00` = 激活成功 + 信息「激活成功」 |

表 B.4 结构为 2 字节：激活状态（0x01 成功 / 0x02 失败）+ 信息（0x00 成功 / 0x01 芯片已激活 / 0x02 VIN 重复）。

## 案例四：AES 加密上报

密钥 AES-128-ECB `000102030405060708090a0b0c0d0e0f`：

1. 明文数据单元按 PKCS#7 填充后 AES 加密，加密方式字段 `03`；
2. BCC 覆盖密文（先加密后校验）；
3. 平台验 BCC → 解密 → 去填充 → 解析信息体；
4. 车端校验正确**不回应答**；
5. 未注入密钥时既解不开也无法按同加密方式应答，只记录。

## 案例五：实时上报与两套规则的差别

| 场景 | 结论 | 应答 |
|---|---|---|
| 车端 | report-accepted | **无**（附录 B.2.1，正确时不做应答） |
| 平台间 | report-accepted | 应答 0x01（正文 5.2.2，正确也必须应答） |

0x08 终端校时是上行命令，应答 0x01；0x80 查询是下行，平台侧判方向不符。

## 案例六：断线补发

补发帧与实时帧数据单元相同，仅命令标识 `02 → 03`。车端补发正确时同样不应答。7 日窗口是对发送方本地存储的要求，平台不因此拒收。
