# 端到端案例：登入应答与加密上报

四个案例都可以用命令复现：

```bash
moon run cmd/main -- case login       # 登入应答端到端
moon run cmd/main -- case encrypted   # AES128 加密上报端到端
moon run cmd/main -- case report      # 实时上报：校验正确时不应答
moon run cmd/main -- case resend      # 断线补发
```

---

## 案例一：登入应答端到端（命令单元 0x01）

### ① 终端发出命令包

```
232301fe4c47574546344135364d463132333435360100251a0b12091e000001383938363036323031383030303132333435363701074241542d413031d5
```

| 偏移 | 字节 | 字段 | 取值 |
|---|---|---|---|
| 0 | `23 23` | 起始符 | `##` |
| 2 | `01` | 命令单元 | 车辆登入 |
| 3 | `fe` | 应答标志 | **命令包**，请求平台应答 |
| 4 | `4c47…3536` | VIN | `LGWEF4A56MF123456` |
| 21 | `01` | 加密方式 | 不加密 |
| 22 | `00 25` | 数据单元长度 | 37 |
| 24 | `1a 0b 12 09 1e 00` | 登入时间 | 2026-11-18 09:30:00 |
| 30 | `00 01` | 登入流水号 | 1 |
| 32 | `3839…3637` | ICCID | `89860620180001234567` |
| 52 | `01` | 储能子系统数 | 1 |
| 53 | `07` | 编码长度 | 7 |
| 54 | `4241542d413031` | 子系统编码 | `BAT-A01` |
| 61 | `d5` | 校验码 | BCC(偏移 2 → 60) |

### ② 平台应答

```
232301014c47574546344135364d4631323334353601000024
```

| 差异点 | 命令包 | 应答包 |
|---|---|---|
| 应答标志 | `fe` | `01` 成功 |
| 数据单元 | 37 字节 | `0000` 空 |
| 加密方式 | `01` | `01`（应答不加密） |
| 校验码 | `d5` | `24`，随内容重算 |

### ③ 终端收到应答后完成登入

- 会话置为在线，登记流水号 1，保存 ICCID；
- 3 分钟内未收到应答应重发；连续 3 次无应答应间隔 30 分钟重连，并把链路恢复前存储的数据补发；
- 平台在线终端数 1。

### ④ 同一 VIN 再次登入

终端再发一帧同类命令包，平台应答：

```
232301034c47574546344135364d4631323334353601000026
```

应答标志 `03` 表示 VIN 重复，终端据此判断需换会话或排查串号。若登入数据单元校验不通过，平台按标准**忽略所接收数据且不应答**，终端靠 3 分钟超时重发兜底。

## 案例二：AES128 加密上报端到端（命令单元 0x02）

密钥由部署方约定并注入：AES128-ECB，`000102030405060708090a0b0c0d0e0f`。

### ① 明文数据单元（37 字节）

```
1a0b12091f0001010201026f0001e2400e1075944e010404b01e01050006f013c80260f688
```

### ② 加密后组帧

```
232302fe4c47574546344135364d463132333435360300304c2229bb4dc2e406c63d054d69f47cbc725f02e50d74f0e58f4b78c3309bcaf466c0da206dbc7e84c0580854cd83ea3af4
```

| 字段 | 值 | 说明 |
|---|---|---|
| 应答标志 | `fe` | 命令包 |
| 加密方式 | `03` | AES128 |
| 数据单元长度 | `0030` = 48 | 37 字节明文经 PKCS#7 填充后为 48 字节密文 |
| 数据单元 | `4c22…3af4` | 密文 |
| 校验码 | `f4` | **在密文之上**计算，与标准「先加密再校验」一致 |

### ③ 平台收到字节流

```
平台结论    : report-accepted
说明        : 校验正确，按标准不做应答
应答帧      : 无（按标准校验正确时不做应答）
```

平台按顺序做三件事：验 BCC（密文）→ 按 `KeyMaterial` 解密 → PKCS#7 去填充 → 交给信息体解析。

### ④ 解密后的字段

```
数据单元    : 37 字节（PKCS#7 填充已去除）
数据采集时间: 2026-11-18 09:31:00
· 整车数据 0x01    SOC 78%  车速 62.3 km/h  里程 12345.6 km  电压 360.0 V  电流 10.0 A
· 车辆位置 0x05    定位有效 true  经度 116.397000  纬度 39.909000
```

### ⑤ 未注入密钥时的行为

```
平台结论    : rejected
说明        : 校验码或解密失败，应答 0x02
应答帧      : 232302024c47574546344135364d4631323334353601000024
```

帧声明 AES128 但平台拿不到密钥时，**拒绝解析并应答 0x02**，绝不当明文解析——否则会把密文当成字段值写进数据库。

### ⑥ 责任划分

| 环节 | 责任方 |
|---|---|
| 加密方式字段、密文承载、先加密再校验的顺序 | 本项目 |
| AES128 加解密、PKCS#7 填充 | 本项目内置（FIPS-197 向量验证） |
| 密钥生成、分发、轮换 | 部署方 |
| RSA 私钥持有与解密 | 部署方；未注入时按拒绝处理 |

32960.3 只定义加密方式字节，密钥管理与通信安全要求属于 GB/T 40855 的范围，因此本项目把密钥做成显式入参而不是隐式约定。

## 案例三：实时上报——校验正确时平台不应答

命令包：

```
232302fe4c47574546344135364d463132333435360100251a0b12091f0001010201026f0001e2400e1075944e010404b01e01050006f013c80260f6880e
```

```
平台结论    : report-accepted
说明        : 校验正确，按标准不做应答
应答帧      : 无
```

校验失败时（数据单元为空或字段越界）才回错误应答：

```
平台结论    : rejected
说明        : 上报数据单元校验失败，应答 0x02；终端应间隔 1min 重发，失败 3 次后停止
应答帧      : 232302024c47574546344135364d4631323334353601000024
```

这就是「实时上报不应答」与「登入必须应答」的区别：前者靠周期与重发机制自愈，后者必须靠应答完成状态迁移。

## 案例四：断线补发

```
09:31 实时  : report-accepted（不应答）
模拟链路中断 09:32 至 09:35，终端缓存三帧
补发 09:32 : resend-accepted（不应答）  帧 232303fe…688cf
补发 09:33 : resend-accepted（不应答）  帧 232303fe…688ce
计数：实时帧 1、补发帧 2
```

补发帧与实时帧数据单元完全相同，仅命令单元由 `02` 改为 `03`、采集时间后移。补发同样**校验正确时不应答**；7 日外的补发应答 `02` 失败，终端据此丢弃该条缓存。
