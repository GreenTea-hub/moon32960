# 标准符合性说明（CONFORMANCE）

本文回答三个问题：目标版本是什么、覆盖到哪里、满足什么条件才算「符合」。凡未做到的部分直接列出，不用「后续」模糊处理。

## 1. 目标版本

**主目标：GB/T 32960.3-2016**《电动汽车远程服务与管理系统技术规范 第 3 部分：通信协议及数据格式》。

理由：2016 版是在网车辆与各级平台实际执行的事实标准，同时是 2025 版切换期的存量基线。2025 版（GB/T 32960.3-2025，2025 年发布并代替 2016 版）列为**第二目标**，见第 5 节差异清单，当前只做帧层兼容（版本差异集中在数据单元字段集，不影响报文结构）。

字段依据：国标正文（表 3 命令标识、表 5 时间定义、表 6 车辆登入、表 7 实时信息上报、表 8 车辆登出、表 15/16 驱动电机、表 21/22 车辆位置、表 19 报警数据）、国标数据类型定义（BYTE / WORD / DWORD / STRING / BYTE[N]），以及标准公开解读文章用于交叉核对。

## 2. 报文结构（已实现）

```
偏移  长度  字段            说明
0     2     起始符          固定 0x23 0x23
2     1     命令单元        见表 3
3     1     应答标志        0x01 成功 / 0x02 失败 / 0x03 VIN 重复 / 0xFE 命令不识别 / 0xFF 无效
4     17    车辆识别码      VIN，ASCII
21    1     数据加密方式    0x01 不加密 / 0x02 RSA / 0x03 AES128 / 0xFE 异常 / 0xFF 无效
22    2     数据单元长度    大端 WORD，有效 0~65531
24    N     数据单元        随命令单元变化
24+N  1     校验码          BCC 异或，范围：偏移 2 至偏移 23+N
```

实现要点：
- WORD 与 DWORD 均按**大端（网络字节序）**读取与写入；
- 校验码覆盖命令单元首字节到数据单元末字节，起始符不参与；
- 解码前逐一检查边界：起始符、最小长度、VIN 合法性、声明长度与实际长度、校验码，任一不符即抛出带定位信息的错误，不 panic。

### 3.3 字段语义

异常与无效码按标准保留，不参与算术：
- BYTE：0xFE 异常、0xFF 无效
- WORD：0xFFFE 异常、0xFFFF 无效
- DWORD：0xFFFFFFFE 异常、0xFFFFFFFF 无效

物理换算按标准计量单元实现：车速 0.1 km/h、累计里程 0.1 km、总电压 0.1 V、总电流 0.1 A（偏移 3000 A）、绝缘电阻 1 kΩ、单体电压 0.001 V、温度偏移 40 ℃、驱动电机转速偏移 32000 r/min、转矩 0.1 N·m 偏移 2000 N·m。

## 4. 兼容性终点

满足以下条件，视为对 GB/T 32960.3-2016 达标：

1. **入站**：任一 2016 版合规终端发出的 0x01/0x02/0x03/0x04/0x07 帧，可逐字段解码。九类信息体任意组合、任意数量（受单帧 65531 字节上限约束）均可解析。
2. **出站**：平台可对上述每一类上行帧生成合规应答帧（同为 24+N+1 结构，数据单元为空，校验码正确）。
3. **拒绝语义**：畸形帧（长度不符、校验码错误、VIN 非法、未知信息类型、声明计数越界）必须被拒绝并给出可定位的错误，同时仍向终端回应答标志 0x02，不允许静默丢包。
4. **会话状态**：登入 → 在线 → 上报/心跳/补发 → 登出 → 关闭，顺序错误一律拒绝；重复登入按 VIN 重复应答 0x03。
5. **补发窗口**：补发数据按 7 日内窗口校验，超窗拒绝。

不在此终点的内容：加密数据单元的实际加解密（第 6 节）、TCP 传输层、2025 版新增字段集。

## 5. 与 2025 版的主要差异（第二目标）

GB/T 32960.3-2025 对 2016 版的主要技术变化，以及对本项目的影响：

| 变化 | 内容 | 本项目处理 |
|---|---|---|
| 版本替代 | 2025 代替 2016 | 帧结构不变，报文层可共存 |
| 新增信息类型 | 动力蓄电池最小并联单元电压、动力蓄电池温度、燃料电池电堆、超级电容器、超级电容器极值 | 未实现，标志位会抛 `UnsupportedInfoType` |
| 删除 | 删除 2016 版动力蓄电池极值数据（0x06） | 0x06 仍按 2016 解析，兼容存量 |
| 删除 | 删除电机控制器输入电压与直流母线电流（驱动电机每项 12 → 9 字节） | 按 2016 的 12 字节解析；2025 报文会出现对齐偏移，列为待做 |
| 登入变更 | 删除「可充电储能子系统数/编码长度/编码」，改为 BMS 个数与蓄电池包编码 | 登入仍按 2016，2025 报文需分支解析 |
| 整车数据 | 车速、总电压、总电流、绝缘电阻取值范围调整 | 码值不变，仅校验范围不同，不影响解码 |
| 位置 | 明确参照 GCJ-02 | 已在文档注明，代码不做坐标系转换 |
| 报警 | 报警等级增至 0~4（新增热事件），新增多类报警位 | 等级按原始码值保留，位解析按 32 位通用实现 |

结论：当前实现**以 2016 为达标基线**，2025 版需要新增分支解码；两者报文头完全一致，网关可按同一入口接受两种版本并分别解析。

## 6. 未覆盖项（明确列出）

| 项 | 现状 | 影响 |
|---|---|---|
| 数据单元加密 | 加密方式字节只透传，不执行 RSA / AES128 | 只能处理 0x01 明文帧；加密帧会被当作明文解析失败 |
| 平台登出 0x06 | 按 8 字节登出格式解析，字段语义未单独建模 | 平台间通信场景不完整 |
| 终端校时 0x08 | 只做应答，未解析校时时间字段 | 校时下发与生效链路未闭环 |
| 平台下行 0x80 | 保留原始负载，未按厂商自定义结构解析 | 下行命令需上层自行解码 |
| TCP 传输层 | 未实现监听、粘包拆包、连接管理 | 当前以帧为单位，靠调用方喂数据 |
| 2025 版数据单元 | 未新增分支 | 见第 5 节 |
| 极值数据字段命名 | 0x06 按 2016 表 20 的 12 项实现 | 若正文另有「单体电池总数」等字段需补齐 |

## 8. 验证方式

- `moon test`：40 条测试，覆盖帧层（黄金帧、往返、校验码、长度、起始符）、字段层（九类信息体往返与异常码）、状态机（顺序、补发窗口）、网关（应答标志与计数）。
- `moon run cmd/main -- case login|report|resend`：三个标准案例，输出报文、字段、应答与后续动作，可直接作为验收演示。
- 黄金帧固定为字符串常量，任何字段布局改动都会让测试失败。

## 9. 与标准正文的差异申报

以下三处需要拿标准正文确认，当前按公开解读实现，测试已把当前行为固定，若正文不同需同步修改实现与测试：

1. **实时上报是否携带信息流水号**：正文 7.2 节公开解读存在两种说法（采集时间后直接接类型标志，或再接 2 字节流水号）。本项目两种布局都支持，默认 `TimestampOnly`，`--with-serial` 切换。
2. **整车数据是否含加速踏板行程值与制动踏板状态**：本实现按 13 字段 20 字节。若正文为 11 字段 19 字节，删两个字段即可。
3. **燃料电池氢系统子项长度**：最高氢温 2 字节、最高氢浓度 2 字节、最高氢压 2 字节的组合按公开解读实现。

这三条不改「是否覆盖」的结论，只影响个别字段的字节位置。
