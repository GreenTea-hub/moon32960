# moon32960

GB/T 32960.3-2016《电动汽车远程服务与管理系统技术规范 第 3 部分：通信协议及数据格式》的 MoonBit 实现：帧编解码、九类信息体解析、会话状态机、平台侧应答与网关路由。

目标版本、覆盖矩阵与兼容性终点见 [docs/CONFORMANCE.md](docs/CONFORMANCE.md)；三个可复现的标准案例见 [docs/EXAMPLES.md](docs/EXAMPLES.md)。

## 能力

- **帧层**：`##` 起始符、命令单元、应答标志、17 位 VIN、加密方式、大端长度、**BCC 校验码**，解码前逐项检查边界；
- **数据单元**：车辆登入（含 ICCID 20 位与可充电储能子系统编码 `n×m`）、车辆登出、平台登入、实时/补发上报、心跳；
- **九类信息体全量**：整车数据（20 字节 13 字段）、驱动电机（每项 12 字节）、燃料电池（探针变长）、发动机、车辆位置（含定位状态位）、极值数据、报警数据（五组故障列表）、储能电压、储能温度；
- **字段语义**：异常码 0xFE / 无效码 0xFF 按 BYTE/WORD/DWORD 分级保留，换算函数返回 `None`，不做算术；
- **会话**：登入 → 在线 → 上报/心跳/补发 → 登出 → 关闭，顺序错误拒绝，补发按 7 日窗口校验；
- **平台应答**：对每类上行帧生成合规应答帧（成功 / 失败 / VIN 重复 / 命令不识别）；
- **审计**：每次接收留一条记录，含 VIN、命令、结论、说明。

## 快速开始

```bash
# 需要 MoonBit 工具链（moonc >= 0.10.7）
moon check
moon test

# 三个标准案例
moon run cmd/main -- case login     # 登入：报文 → 字段 → 应答 → 后续动作
moon run cmd/main -- case report    # 实时上报
moon run cmd/main -- case resend    # 断线补发

# 解析一帧
moon run cmd/main -- decode 232301014c47574546344135364d463132333435360100251a0b12091e000001383938363036323031383030303132333435363701074241542d4130312a
```

├── cmd/main/          CLI 与三个案例
└── docs/              符合性说明、协议对照、案例

## 标准对齐状态

以 **GB/T 32960.3-2016** 为达标基线：入站可逐字段解析，出站可生成合规应答，畸形帧拒绝并应答失败，会话与补发窗口按标准约束。

**尚未实现**：数据单元加密（RSA / AES128）只透传加密方式字节；TCP 传输层、粘包拆包；GB/T 32960.3-2025 新增信息类型与登入变更。完整清单见 CONFORMANCE.md 第 6 节。

有三处字段布局依据公开解读、需与标准正文最终核对，已在 CONFORMANCE.md 第 9 节逐条列明，测试固定了当前行为。
