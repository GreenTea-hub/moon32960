# moon32960

GB/T 32960（电动汽车远程服务与管理系统 · 通信协议及数据格式）的 MoonBit 实现：帧编解码、会话状态机、平台侧网关路由与一致性测试素材。

> 目标不是做一个 demo，而是补齐 MoonBit 生态里缺失的「车联网国家强制协议」基础库：帧层可复用、网关层可替换传输、测试层可回归。

## 当前能力（第一期骨架）

- 帧层：`##` 起始符 + 命令标识 + 应答标志 + 17 字节 VIN + 加密方式 + 数据单元长度（大端）的编解码，全部带边界检查；
- 枚举：命令（登入/登出/实时/补发/心跳/校时/平台下行）、应答标志、加密方式，均保留 `Unknown` 前向兼容分支；
- 校验：VIN（17 位、ASCII、排除 I/O/Q）、时间（6 字节、年份按 2000 起算、字段范围检查）、十六进制往返；
- 数据单元：车辆登入、登出、实时上报（整车状态 + 位置两类信息项，类型 + 长度 + 体 的分段格式）；
- 会话：登入/上报/心跳/登出状态机，区分实时上报与补发计数；
- 网关：纯逻辑会话表，按 VIN 路由，未知 VIN 拒绝，重复登入按「恢复会话」处理；
- CLI：`decode` / `encode` / `demo`；
- 测试：25 条，覆盖黄金帧、往返不变量、错误分支、状态机与网关路由。

未实现（见路线图）：数据单元加密（RSA/AES128）、补发窗口与去重策略、TCP 监听、2025 版字段差异。

## 快速开始

```bash
# 需要 MoonBit 工具链（moonc >= 0.10.7）
moon check
moon test

# 环回演示：编码 -> 解码 -> 打印字段
moon run cmd/main -- demo

# 解码一帧（十六进制）
moon run cmd/main -- decode 23230101475245454e313233343536373839303132010000

# 由 VIN、命令与负载构造一帧
moon run cmd/main -- encode GREEN123456789012 vehicle-login 1a0b100f00000001
```

```

├── moon.pkg              # 根包依赖
├── errors.mbt            # FrameError 错误类型
├── command.mbt           # 命令 / 应答标志 / 加密方式枚举
├── codec.mbt             # 字节、十六进制、VIN、时间
├── frame.mbt             # 帧头编解码
├── login.mbt             # 登入 / 登出数据单元
├── realtime.mbt          # 实时上报数据单元与信息项
├── session.mbt           # 终端会话状态机
├── gateway.mbt           # 平台侧会话表与路由
├── *_test.mbt            # 黑盒测试（25 条）
├── cmd/main/             # CLI
└── docs/PROTOCOL.md      # 协议字段说明与待核对清单
```

## 对齐状态（重要）

帧头的字段语义、命令集与加密方式取值按公开资料实现；**数据单元的字段级布局目前是本仓库定义的「字典布局」**，用于先把编解码、状态机、网关跑通，尚未逐字段对齐标准正文。`docs/PROTOCOL.md` 列出了每一处待核对项，不以「一致性」自居。

## 合规

- 仓库不收录 GB/T 标准原文（标准文本受版权保护），只描述字段语义并引用条款编号；
- 未移植任何第三方实现代码；
- 许可证：[Apache-2.0](LICENSE)。

## 路线图

1. 按标准正文核对数据单元字段布局，补 2016/2025 双版本差异表；
2. 补发语义：时间窗、去重、失败重试；
3. 加密路径：RSA / AES128，密钥来源与错误处理；
4. TCP 网关：接入、断线重连、限流、落库；
5. 一致性测试仪：畸形帧库 + fuzz + 与第三方实现互操作。
